# Qwen3.8-27B context-cache calibration (RTX 4090)

This report records correctness and capacity evidence for the tiered context-cache workload. It is
not a latency, throughput, or performance result.

## Target and method

Measured on 2026-09-10 with:

- NVIDIA GeForce RTX 4090, compute capability 8.9, 24,564 MiB, driver 595.84;
- CUDA 13.3 (`cuda_13.3.r13.3/compiler.38244171_0`);
- `/models/qwen3_8_27b.ninfer`, 18,210,531,328 bytes, `qwen3_8_27b` groupwise-int;
- task base `8b7070f831d663fbd0c576448f10533c8bb10f5d` plus the changes described here;
- `max-context=128000`, `max-concurrency=4`, `kv-capacity=auto`, `rk4v4-e8`, MTP,
  `draft-tokens=3`, optimized LM draft head, and Vision disabled.

The reproducible capacity probe is:

```bash
export NINFER_QWEN3_8_27B_WEIGHTS=/models/qwen3_8_27b.ninfer
NINFER_PREFIX_REAL_SCENARIO=target-cache-calibration \
  build-agent-verify/tests/ninfer_qwen3_6_27b_prefix_real_test
```

No external context-cost file was supplied. The existing resolver selected `generic-default` for
both transfer and prefill because the compiled table has no matching RTX 4090/Qwen3.8 groupwise-int
entry. This report does not invent a preset.

| private/shared catalog entries | 8 / 4 |
| long anchors per continuation | 2 |
| weights arena | 17,901,798,400 bytes |
| sequence arena | 5,341,441,792 bytes |
| workspace arena | 159,981,568 bytes |
| minimum runtime reservation | 4,174,114,560 bytes |
| resolved runtime reservation | 5,862,133,504 bytes |
| available after weights/startup | 6,935,937,024 / 1,382,678,528 bytes |
| automatic sizing headroom | 1,073,741,824 bytes |

The 128,000-token value is a logical ceiling for each admitted request, not four pre-reserved
full-length contexts. The resolved shared physical KV budget is 219,264 tokens, well below 512,000;
Program admission proves each concrete request set against this budget.

`MemorySummary::gdn_state_bytes` is 1,231,552,512 bytes for the eight-slot Device pool, or
153,944,064 bytes (146.8125 MiB) per slot. That is the measured geometry behind the approximate
147 MiB GDN-only estimate. It is not the complete snapshot State payload. With target plus MTP
continuation state, a real snapshot reports 307,908,608 bytes (293.6445 MiB) of State per image.

## Exact Host snapshot assembly charge

The delayed-spill probe reports:

```text
metadata=1000
state=307908608
main_kv=4194304
backend_kv=262144
transfer=312366056
staging=312366056
resident=624732112
```

`transfer` is exactly metadata + State + Main KV + MTP KV. The bounded writer reserves two complete
images: the pinned D2H staging backing and the equal-sized assembly/output image, so `resident` is
exactly `2 * transfer`. The quota-rejection regression sets the byte capacity below this value and
observes rejection before D2H submission with zero queued/in-flight/reserved jobs, live buffers,
source pins, or pending transaction afterward.

## Deterministic correctness fixture

Reproduce all comparison rows with:

```bash
export NINFER_QWEN3_8_27B_WEIGHTS=/models/qwen3_8_27b.ninfer
NINFER_PREFIX_REAL_SCENARIO=cache-fixture-equivalence \
NINFER_REPORT_CACHE_FIXTURE_HASHES=1 \
  build-agent-verify/tests/ninfer_qwen3_6_27b_prefix_real_test
```

Greedy two-token continuations produced the same token-ID FNV-1a fixture hash:

| Path | Reuse observation | Fixture hash |
|---|---|---:|
| cache disabled | root, zero reused tokens | 16493017374143550425 |
| existing anonymous prefix cache | exact non-session Device reuse; no Host/shared/anchors | 16493017374143550425 |
| Device checkpoint | exact non-root reuse | 16493017374143550425 |
| Host checkpoint | D2H demotion followed by exact H2D restore | 16493017374143550425 |

The existing-cache row clears session identity and exercises anonymous exact-prefix reuse with
`device_state_slots=1`, `max_private_continuations=2`, zero Host State and KV capacity, zero shared
prefixes, and zero long anchors. All four rows are produced by the same
`cache-fixture-equivalence` command above with the same rendered initial exchange, continuation,
greedy settings, and token hash function. Set `NINFER_REPORT_CACHE_FIXTURE_HASHES=1` to print the
four hashes. The test also requires State, Main KV, and MTP KV transfer counters on the Host path.
This proves output equivalence for this deterministic fixture; it does not establish performance.

## Four-request constrained-pressure regression

The target artifact also passed the finite maximal-root fallback scenario:

```bash
export NINFER_QWEN3_8_27B_WEIGHTS=/models/qwen3_8_27b.ninfer
NINFER_PREFIX_REAL_SCENARIO=four-request-root-fallback \
  build-agent-verify/tests/ninfer_qwen3_6_27b_prefix_real_test
```

The scenario fills all four Device State slots with explicit conversation heads, configures zero
extra Device State slots and zero Host State/KV capacity, then admits four concurrent root
requests. It requires all four streaming requests to be active together, a finite maximal-root
fallback, at least four actually reclaimed Device State slots, root reuse paths, zero Host
occupancy, and complete terminal cleanup. The command returned `ok` on the target above.

## Testing validation record

Testing ran the canonical repository gate from the task worktree with the provisioned Python and
the Qwen3.8 groupwise artifact:

```bash
NINFER_VERIFY_PYTHON=/opt/ninfer-venv/bin/python \
NINFER_VERIFY_EVAL_PYTHON=/opt/ninfer-venv/bin/python \
NINFER_QWEN3_8_27B_WEIGHTS=/models/qwen3_8_27b.ninfer \
  bash .agent/verify.sh
```

Result on 2026-09-10: PASS. Linux launcher checks passed; artifact/converter pytest reported 77
passes; evaluation coordinator reported 19 passes; the Release sm_89 application/test build
passed; CTest reported 104 tests, zero failures, and six skips in 322.65 seconds. The real Qwen3.8
prefix test executed and passed in 124.97 seconds. Skips were the unavailable Qwen3.6 score/load
artifact tests, Qwen3.6-35B-A3B real/DFlash tests, and the unsupported NVFP4 A4 test. The official
tokenizer-gated frontend lineage cases did not execute because `NINFER_QWEN3_6_27B_HF_DIR` was not
available; the self-contained structural frontend cases and ResourceManager exact-lineage
regressions passed.

Focused evidence in the same worktree:

- `ctest --test-dir build-agent-verify -R
  '^(ninfer_resource_manager_test|ninfer_qwen3_6_frontend_test)$' --output-on-failure`: two passes,
  zero failures; direct frontend execution explicitly reported the official-tokenizer skip.
- `target-cache-calibration`: passed with the budgets and geometry recorded above.
- `cache-fixture-equivalence`: passed and printed the four identical hashes recorded above.
- `four-request-root-fallback`: passed on the RTX 4090 artifact.

The ResourceManager suite includes cancellation after committed pressure (and asserts that only
the Program-reported committed subset reaches reclaimed-capacity totals), supersession while the
prior conversation head is claimed, subsequent settlement/dependency cleanup, and zero-page alias
reclamation.

## Limitations

No performance benchmark was run, so disabled-cache, Device-reuse, and Host-reuse latency or
throughput remain unverified. NVFP4 requires unsupported target hardware and is outside this
groupwise-int calibration. The snapshot accounting fixture is deliberately short; byte accounting
is exact for its concrete State/KV payload, while longer conversations consume additional complete
KV page extents.
